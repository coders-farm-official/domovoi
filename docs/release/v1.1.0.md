# Domovoi 1.1.0

**The home computer system that just works. Keeps it in the house.**

Domovoi turns a computer you already own into your home's own system: your
music, movies, audiobooks, files and documents in one place, playing in every
room and on your phone. No cloud, no subscription, and nothing leaves your
network unless you say so.

This release follows 1.0.0. It makes the menu simpler, makes a new Domovoi
easier to claim, and makes the rooms more dependable: no more rooms stuck
"thinking", fewer false wakes, and a history that records every turn. If this
is your first look, start with the
[README](https://github.com/coders-farm-official/domovoi#readme).

## What is new since 1.0.0

### A simpler menu

- The dashboard's sidebar is now **Home · Chat · Media ▸ · Tools ▸ ·
  Plugins**. Media holds Music, Podcasts, Audiobooks and Videos (and a
  plugin's page such as Stations); Tools holds News, Calendar and Files. A
  group with one page shows that page on its own, and Media starts open.
- **People** moved into Settings, under **Household** (the group that was
  called "Rooms & devices": Rooms, People, Phones & browsers, Printers &
  scanners). Old links to People still land there, and a phone bar that had
  People keeps its tab. **App layout** moved to **System**.
- The Android app has the same groups in its side menu, with Media and Tools
  headings on Home. The bottom bar stays home · music · videos · chat.
- **An admin can rearrange the menu for the whole house** in Settings →
  System → App layout → **Menu**: rename the groups, add and delete groups,
  move any page (plugin pages, Chat and Plugins too) into a group or to the
  top, and change the order, with a live preview. It is kept on the server,
  so every browser shows it, and open dashboards change as soon as it is
  saved. **Reset to default** brings the usual menu back. Nothing needs
  doing: without a saved menu the default stays. The phone app keeps its own
  layout.
- Plugin authors can put a page in the Media or Tools group with the new
  `nav_group` key ([plugin development](https://github.com/coders-farm-official/domovoi/blob/main/docs/PLUGIN_DEVELOPMENT.md)).

### A welcome on a new Domovoi

- A Domovoi nobody has claimed now greets every page load of its dashboard
  with a welcome that does the claim itself: the setup code, then the admin
  password, with "where's my code?" for your kind of server (the Windows
  installer's last page, or the file on Linux). **Not now** puts it away for
  that browser; Home's "claim it" brings it back.
- Right after the claim, **"You're all set!"** shows the household token with
  a copy button, says it is not the admin password, and offers to make an
  easier one of your own.
- **The Android app** shows "This Domovoi isn't set up yet" for a server
  nobody has claimed, instead of a workspace, with **Check again**, a link to
  the dashboard, this phone's own media, or a different server.
- A browser that isn't connected yet to a claimed Domovoi is greeted once
  with "Enter this home's household token to connect this browser", with
  "Where do I find it?" and **Not now**. Home then shows a **Connect this
  browser** button.

### No more rooms stuck "thinking"

When speech recognition on the server got stuck, every room sat in its yellow
"thinking" ring until someone restarted things, and the history showed
nothing. Now:

- **Every stage before a reply has a time limit.** Slow but working AI models
  are given room (a cold model load plus two model calls), and chat is
  outside it. When a limit is reached the room says *"Sorry, that took too
  long and I lost track of it. Please try again."* and listens again.
- **Settings → System → Health** says *speech recognition is stuck* when it
  is, and warns for a while after a request timed out. If it stays stuck for
  10 minutes, Domovoi restarts itself on the Linux and Windows installs
  (never during an update or a plugin install, and at most once an hour).
- **Rooms stop waiting on their own.** If the server sends nothing within
  75 seconds of a request, or goes silent for 240 seconds part-way through, the
  room shows red, says *"Sorry, I didn't get an answer from the server"*, and
  listens for the wake word again. Each room's **Reply deadline** and **Reply
  backstop** settings change these; 0 turns either off. The room's Health card
  shows how long it has been waiting.

### Room history records every turn

- What was said shows up in the room's history as soon as it is heard,
  marked *waiting for an answer…*. The same entry then gets the reply, or
  says *no answer — timed out* (or *something went wrong*, *interrupted*,
  *Domovoi restarted*). A request that couldn't be understood shows as
  *couldn't make out what was said*, with its time and length, and one that
  sounded like background talk as ignored.
- The dashboard's room drawer and the Android app refresh while an entry is
  waiting.
- If you have scripts that read a room's conversations from the API, they get
  three new fields (`status`, `no_answer_reason`, `audio_ms`), and the
  text is empty on a turn nobody could make out.

### Fewer false wakes

- When a room wakes on the TV and records a long stretch of talk, Domovoi
  now stays silent instead of answering it. A clear command at the start
  ("play some jazz in the kitchen") is still done, and a clear question or
  one addressed to Domovoi by name is still answered. A long capture never
  opens a follow-up question.
- Two new room settings: **Wake confirmation** (how long the wake word must
  be heard before the room wakes; raise it if a TV or phone sets the room
  off) and **Wake pause after a turn** (a short pause in listening after a
  turn that went wrong, so a TV repeating the word can't start the next one
  at once).
- Settings that are numbers now have sliders for the common ones, arrows
  that move in sensible steps (Wake sensitivity no longer jumps to the top
  in one click), and scrolling the page never changes a value.

### Wake-word training and clips

- Recording more clips for a word now adds to them instead of replacing
  them, across takes and rooms, until you train. Each clip shows the room it
  was recorded in, and the clips can be filtered and sorted by room.
- **Delete all clips** clears a word's clips (it asks first, naming the
  count).
- A word that is already trained can record more and **Train again**; its
  current model stays in use until the new one is ready.
- **Stop** ends the recording in the room that is actually recording, and
  the room's light shows steady white for each clip and goes back to idle
  when you stop.
- The trainer's one-time download is more reliable.

### Memory

- **Settings → System → Health → memory** (admin) says how much memory
  programs use and how much is file cache, and lists what uses it: each
  Domovoi service, each container and the largest other programs. It turns
  amber only when less than a tenth is left for programs.
- **On a Windows install**, Domovoi now hands file cache back to Windows
  every 2 minutes, and the default share of the PC is smaller (at most
  32 GB). An admin sets how much memory and how many processor cores Domovoi
  may use in Health → **This PC**, with **Restart Domovoi now** to apply it.
  This card comes with this release's Windows side.
- **Domovoi comes back by itself when Windows updates WSL.** Before, a WSL
  update could stop Domovoi until someone started it again. The tray icon
  says "Windows updated WSL, starting again..." while it waits.
- **Windows: Save logs** now includes the server's own log as well.

### Music

- Music in a room holds 3 seconds before the first note, so a short Wi-Fi
  dropout is no longer heard as a chop. A song starts about 2 seconds later,
  and pause and skip are heard that much later; stop is still immediate. Each
  room's **Music buffer** setting changes it (0 to 10 seconds).
- **"Play <song> by <artist>"** for a song you don't have, by an artist you
  do, now streams the song if a streaming media plugin is installed, or asks
  "Want me to shuffle <artist> instead?" It no longer asks "Did you mean
  <artist>?" and then shuffles the artist.
- Adding a found song no longer refuses it as "already in your library" just
  because one of your songs has a title that is a word of its name.
- Rooms keep playing music after your router gives the server a new
  address. Before, music stopped right after it started.

### Notifications and settings

- Notifications now appear at the top of the page, bigger, in one stack,
  with timer and reminder alerts just under them.
- A plugin upgrade that needs a newer copy of its own packages no longer
  fails ("install would change the version of already-installed
  distribution(s)"). Update Domovoi first, then upgrade the plugin.
- In the Documents editor, selecting text across several lines no longer
  drops the selection.

### Android fixes

- Calendar events you add or change keep the right time when your phone is
  in another time zone than the house. An event whose start can't be read is
  no longer shown as happening now.
- The document editor's writing follows the phone's text size setting.
- Controls a phone can't use are gone instead of failing: generating,
  cancelling and deleting images (they stay on the dashboard), and starting a
  call between two rooms (start it from the dashboard). **Add to library**
  shows only when adding can work.
- The pairing screen no longer appears and vanishes by itself.
- When the server asks the phone to wait, or an address doesn't prove it is
  your Domovoi, the app says so instead of "offline?".
- Health no longer shows a green tick for the container guard on a server
  that hasn't checked; it says "not checked yet".
- Screen readers name each "warn again" button, and "1 chapter" is no longer
  "1 chapters".
- Room history refreshes only while the app is on screen.

### Installing

- A fresh Linux install now pins the vision model's current build. If the
  vision model doesn't match, the install finishes without it and says so;
  an admin can add it later in Settings → Chat & AI → Models. Installed
  servers are not affected.
- The installer says plainly when another copy of Ollama already uses its
  port, and waits longer for Ollama to start.
- A Windows update no longer stops when the Ubuntu download site is down and
  the install already has the image it needs.

## Known limits

- **The memory and processor limits are for Windows installs only.** A Linux
  server has no such ceiling in Domovoi.
- **The household menu is for the dashboard.** The phone app keeps its own
  layout, and the phone bar card is still per browser.
- **Generating images and starting a call between two rooms** are done from
  the dashboard, not the phone.
- **The Windows installer and the Windows room Setup are not code-signed.**
  Windows SmartScreen will ask before running them.
- **No encryption on your home network.** Domovoi uses plain HTTP inside the
  house and has one shared household key, plus one admin password. It is not
  meant to be reachable from the internet, so do not port-forward its ports.
  The [security notes](https://github.com/coders-farm-official/domovoi/blob/main/docs/SECURITY_PRIVACY.md)
  say plainly what it does and does not guard.

## Upgrading

- **Linux servers:** Settings, System, About & updates, **Update Domovoi**.
  The update applies the three database changes by itself and rolls back by
  itself if the new code does not come up healthy. There is nothing to run by
  hand.
- **Windows installs:** use the dashboard's **Update Domovoi** (Settings,
  System, About & updates). It updates both halves, and the Windows side
  brings the memory card, the WSL recovery and the fuller Save logs. On a
  1.0.0 install, the tray menu's **Update Domovoi...** stops before changing
  anything; this release fixes it, so use the dashboard this once.
- **Rooms:** a room takes the new reply deadline, music buffer, wake
  confirmation and training lights with **Upgrade room** in its Overview on
  the dashboard.
- **Android:** install or update the app from Google Play. A phone can also get
  it from your own server: press **Download the app to this server** on the
  dashboard once, then scan the QR code from the phone.
